# 재귀란?

재귀는 어떤 것을 정의할 때, 자기 자신을 참조하는 것을 의미한다.

프로그래밍에서 **재귀 함수**(Recursive Call)는 함수 내부에서 자기 자신을 다시 호출하여 문제를 해결하는 방식을 말한다.

<br>

## 재귀 함수의 두 가지 핵심 요소

모든 재귀 함수는 다음과 같은 두 가지 핵심 요소를 반드시 포함해야 한다.

**1. Base Case(기본 케이스)**
- 재귀 호출을 멈추는 **종료 조건**으로, 재귀가 무한히 반복되는 것을 막는다.
- Base Case가 없으면 함수는 계속해서 자기 자신을 호출하다가 **스택 오버플로우**(Stack Overflow) 오류를 일으키며 프로그램이 강제 종료된다.


**2. Recursive Call(재귀 호출)**
- 함수 내부에서 자기 자신을 호출하는 부분이다.
- 이 호출을 통해 문제를 점점 더 작은 단위로 쪼개 나간다.

<br>
<br>

### 팩토리얼

팩토리얼이 재귀 함수의 대표적인 예시이다.

```java
public static int fatorial(int n) {
    if(n == 0) { // Base Case (기본 케이스)
        return 1;
    }
    // Recursive Call (재귀 호출)
    return fatorial(n - 1) * n;
}
```

> `factorial(num-1)`이 바로 자기 자신을 호출하는 부분이다.

<br>
<br>

### 재귀 함수의 동작 원리

재귀 함수가 호출될 때, 각 함수 호출은 **스택 메모리**에 쌓인다.

다음과 같이 `factorial(4)`를 호출하면 다음과 같은 순서로 실행된다.

![image](https://github.com/user-attachments/assets/282f458f-dd6a-405a-a911-e74352dd08dc)

**1. 재귀 호출**:
- 함수가 자기 자신을 계속 호출하며 문제를 더 작은 단위로 쪼개나간다. 
- 이 과정은 스택에 차곡차곡 쌓인다.

**2. 기본 케이스**:
- 미리 정해둔 **종료 조건**에 도달할 때까지 재귀 호출이 계속된다.
- 이 기본 케이스가 무한 루프를 막아주는 필수적인 부분이다.

![image](https://github.com/user-attachments/assets/4fa22f20-92c8-4539-b983-ba68b5244b8e)

**3. 반환**
- 기본 케이스에 도달하면 더 이상 호출하지 않고, **설정된 반환값을 가지고 이전 단계의 함수 호출로 돌아온다.**

**4. 역순 반복**
- 스택에 쌓였던 호출들이 쌓인 순서의 **역순**으로 하나씩 해결되며 값을 계산해 최종 결과를 반환한다.

<br>
<br>

### 피보나치 수열 

피보나치 수열은 재귀의 개념을 명확히 보여주는 또 다른 대표적인 예시이다.

피보나치 수열은 `첫째 항`과 `둘째 항`이 `1`이며, 그 뒤의 모든 항은 바로 앞 두항의 합으로 이어지는 수열이다.

```java
public static int fibonacci(int n) {
    // 1. Base Case (기본 케이스)
    // 재귀 호출을 멈추는 조건입니다. n이 0 또는 1일 때 더 이상 재귀 호출을 하지 않고 값을 반환합니다.
    if (n <= 1) { 
        return n; // n이 0이면 0을, n이 1이면 1을 반환
    }
    
    // 2. Recursive Call (재귀 호출)
    // n-1번째 항과 n-2번째 항의 값을 얻기 위해 함수 자신을 두 번 호출합니다.
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

피보나치 수열의 재귀 함수는 **한 재귀 함수의 호출이 끝나기까지 대기한다**는 **호출 스택의 동작 원리**를 명확하게 보여준다.

`return fibonacci(n - 1) + fibonacci(n - 2);` 문장을 실행하려면, 먼저 `fibonacci(n - 1)`의 반환값을 알아야 하고,  

그 다음, `fibonacci(n - 2)`의 반환값을 알아야 한다.  이 두 값이 모두 확보되기 전까지는 `+` 연산을 수행할 수 없다.  


![image](https://github.com/user-attachments/assets/cea06fe6-44a6-4a94-b56f-5fcbec0ddd36)


> 이 함수는 `fibonacci(n - 1)`과 `fibonacci(n - 2)`를 두 번 호출하기 때문에, n이 커질 수록 같은 계산을 여러 번 반복하게 되어 비효율적이다.
>
> 예를 들어, `fibonacci(5)`를 계산할 때, `fibonacci(2)`이 여러 번 호출된다.

## 하노이 탑(Tower of Hanoi) 

하노이 탑은 재귀의 강력함을 보여주는 고전적인 문제이다.   

세 개의 기둥(A, B, C)과 크기가 다른 N개의 원반이 주어지며, 모든 원반을 한 기둥(A)에서 다른 기둥(C)으로 옮기는 것이 목표이다.

<br>

> 💡 규칙
>
> 1. 한 번에 하나의 원반만 옮길 수 있습니다.
>
> 2. 큰 원반은 절대 작은 원반 위에 올 수 없습니다.
> 
> 3. 세 개의 기둥(시작 기둥, 보조 기둥, 목표 기둥)만 사용할 수 있습니다.

## 재귀 함수의 장담과 단점

**장점:**
- **코드의 간결성:** 반복문을 사용하는 것보다 코드가 더 직관적이고 간결해진다. 
- **변수 사용 감소:**: 상태를 저장하기 위해 별도의 변수를 만들 필요 없이, 재귀 호출 시 매개변수를 통해 상태를 전달할 수 있다.

**단점:**
- **메모리 사용량 증가:** 함수가 호출될 때마다 스택 메모리에 매개변수, 지역 변수, 복귀 주소 등이 저장되어 메모리 사용량이 크게 늘어나며, 재귀가 깊어지면 **스택 오버플로우**가 발생할 수 있다.
- **성능 저하:** 함수 호출 시 발생하는 추가적인 오버헤드 때문에 반복문에 비해 속도가 느릴 수 있다.
