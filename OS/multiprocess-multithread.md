## 멀티 태스킹(Multitasking)
### 정의
- 운영체제가 여러 작업(프로세스, 테스크 등)을 **동시에 수행하는 것처럼 보이게 하는 기능**
- 실제로 CPU가 작업 가늘 매우 빠르게 전환하면서 처리하는 방식

<br>
 
### 특징
- CPU는 한 번에 하나의 작업만 처리하지만, 작업 전환이 빠르게 일어나 사용자 입장에서는 **여러 작업이 동시에 실행되는 것처럼 느껴짐**
- 예시: 음악을 들으면서 웹 서핑하고, 파일도 동시에 다운로드하는 경우
 
<br>
 
### 멀티 태스킹이 여러 작업을 동시에 처리하는 방식
- **시분할 방식(Time Sharing)**: CPU 시간을 나눠 여러 작업에 돌아가며 할당
- **멀티 프로세싱(Multiprocessing)**: 여러 CPU 또는 멀티코어를 통해 **물리적으로 병렬 처리**
- **멀티 프로세스(Multi Process)**: 여러 개의 독립된 프로세스를 생성하여 각각 병렬로 작업 수행
- **멀티 스레드(Multi Thread)**: 하나의 프로세스 내에서 여러 스레드를 병렬 실행

<br>

> **멀티태스킹**은 CPU 자원을 효율적으로 분할하여 여러 작업이 동시에 수행되는 것처럼 보이게 하는 **소프트웨어적 기법**이다. 반면 **멀티프로세싱**은 여러 CPU 코어가 실제로 병렬로 작업을 수행하는 **하드웨어적 접근법**이다.

<br>
<br>

## 멀티 프로세싱(Multiprocessing)
### 정의
- 하드웨어적으로 두 개 이상의 CPU나 멀티코어 CPU를 활용하여 **실제로 여러 작업을 동시에 병렬로 처리하는 방식**

<br>
 
### 특징
- **물리적으로 여러 작업이 동시에 실행됨**
- 운영체제와 하드웨어 모두 멀티코어 자원이 필요
- CPU 코어 수가 많을수록 **병렬 처리 성능이 좋아짐**

<br>
<br>

## 멀티 프로세스(Multi Process)
### 정의
- 하나의 응용 프로그램이 여러 개의 **독립적인 프로세스**를 생성하여 각가 병렬로 작업을 수행하는 구조

<br>
 
### 특징
- 각 프로세스는 **독립적인 메모리 공간**을 가짐 → 메모리 간섭 없음
- 한 프로세스 오류로 종료되어도 다른 프로세스에는 영향 없음 → **안정성 높음**
- 프로세스 간 통신(IPC)이 필요 → 구현 복잡, 통신 속도 느림
- **문맥 교환(Context Switching) 비용이 큼** → 자원 소모가 많음

<br>
<br>

## 멀티 스레드(Multi Thread)
### 정의
- 하나의 프로세스 안에서 여러 개의 스레드를 생성하여 **병렬적으로 작업을 수행하느 구조**

<br>
 
### 특징
- 스레드들은 프로세스 내 Code, Data, Heap 메모리를 **공유함**
- 스택 메모리만 각 스레드별로 따로 소유
- 공유 메모리 덕분에 **스레드 간 통신이 빠르고 간단함**
- 동기화(Synchronization) 필요 → 공유 자원 충돌 위험 있음
- 한 스레드의 문제 발생 시 **전체 프로세스에 영향을 줄 수 있음 → 안정성은 멀티 프로세스보다 낮음

<br>
<br>

## 멀티 프로세스 대신 멀티 스레드를 사용하는 이유

<br>

| 이유                | 설명                                            |
| ----------------- | --------------------------------------------- |
| **메모리 효율**        | 스레드는 메모리 공간을 공유하기 때문에 **전체 메모리 사용량이 적고 효율적임** |
| **통신 속도**         | 프로세스 간 통신(IPC)보다 **스레드 간 통신이 훨씬 빠르고 간단함**     |
| **응답 속도 및 처리 속도** | 빠른 작업 전환과 실행으로 **실시간 처리나 응답성이 중요한 서비스에 적합**   |
| **문맥 교환 오버헤드 감소** | 스레드는 문맥 교환 시 비용이 적어 **많은 작업을 가볍게 처리 가능**      |
| **개발 구조의 유연성**    | 하나의 프로그램 내에서 모듈화된 병렬 처리가 가능해 **구조 설계에 유리함**   |

<br>

> 멀티 프로세스는 독립된 메모리 공간으로 안정성이 높지만, 문맥 교환 비용과 프로세스 간 통신 비용이 커 효율이 떨어질 수 있다. 멀티 스레드는 메모리를 공유해 통신이 빠르고 오버헤드가 적지만, 동기화 문제로 안정성은 다소 낮다. 때문에 실시간 처리나 사용자 인터랙션이 중요한 시스템에서는 **멀티 스레드를 선호하는 경향**이 있다.
