# 프로세스(Process)와 쓰레드(Thread)

- **프로그램**
  - 명령어, 코드 및 정적인 데이터의 묶음이며 아직 실행되지 않은 상태를 의미
- **프로세스**
  - 실행 중인 프로그램
  - 운영체제로부터 시스템 자원을 할당 받는 작업의 단위

<br>

## 프로세스(Process)
- **실행 중인 프로그램**으로, 디스크에 저장된 프로그램이 **메모리에 적재되어 CPU 자원을 할당받아 동작하는 실행 단위**
- 하나의 프로세스는 최소 1개의 **메인 스레드**를 포함하며, 필요에 따라 여러 스레드를 가질 수 있음

<br>

**프로세스 메모리 영역:**
- `Code`: 실행할 프로그램의 코드가 저장되는 영역
- `Data`: 전역 변수, 정적 변수 등 초기화된 데이터가 저장되는 영역
- `Stack`: 함수 호출 시의 지역 변수, 매개변수, 리턴 주소 등이 저장되는 임시 메모리 영역
- `Heap`: 동적으로 할당되는 메모리

<br>

### 멀티 프로세스(Multi-Process)
- 하나의 작업을 여러 개의 프로세스가 나눠서 처리하는 방식
- 각 프로세스는 실행 시 고유한 메모리 공간을 할당받기 때문에, 프로세스 수가 많을수록 메모리 사용량이 증가
- 프로세스 간 데이터 공유가 불가능하므로, 통신을 위해 IPC(Inter-Process Communication) 기법이 필요
- 프로세스 간 전환(Context Switching)에 따른 비용이 큼
- 하나의 프로세스에 문제가 생겨도 다른 프로세스에는 영향을 주지 않는 장점이 있음

> Ex: Google Chrome
>
> 크롬은 탭마다 별도의 Renderer Process를 사용하며, Browser Process, GPU Process, Plugin Process 등 다양한 프로세스가 동시에 동작함으로써 안정성과 성능을 높인다.

<br>

### 프로세스 상태

- **생성(Create)**
  - 사용자에 의해 프로세스가 생성된 상태
- **준비(Ready)**
  - CPU를 할당 받을 수 있는 상태
  - 준비 리스트: 각각 우선순위를 부여해서 우선순위가 높은 프로세스가 다음 순서에 CPU를 할당 받는다.
- **실행(Running)**
  - 프로세스가 CPU를 할당 받아 동작 중인 상태
- **대기(Waiting)**
  - 프로세스 실행 중 입출력 처리 등으로 인해 CPU를 양도하고 처리가 완료되기까지 대기 리스트에서 기다리는 상태
  - 대기 리스트: 우선순위가 존재하지 않음
- **완료(Complete)**
  - 프로세스가 CPU를 할당 받아 수행을 종료한 상태

<br>

### 프로세스 상태 전이

![image](https://github.com/user-attachments/assets/c41d07d6-5516-4b37-b3fe-1de86889c928)

- **디스패치(Dispatch)**
  - 준비 상태에 있는 여러 프로세스 중에서 실행할 프로세스를 **스케줄러**가 선정하여 CPU를 할당하는 과정 
  - CPU 할당 과정에서 **문맥 교환**이 발생하며, 프로세스 상태가 **준비 → 실행**으로 전이됨
  - 준비 리스트에 있는 프로세스들은 CPU 할당을 기다리는 상태

<br>

- **타임아웃(Timeout)**
  - CPU를 할당받은 프로세스가 정해진 시간(Time Slice)을 모두 사용하면, 스케줄러가 현재 상태(PCB)를 저장하고 CPU를 반납하도록 강제
  - 이 과정은 **선점**(Preemption)으로 불리며, 프로세스 상태가 실행 → 준비 상태로 전이
  - 타임 슬라이스는 Round-Robin 스케줄링에서 실행 단위 시간으로 사용
    - 너무 짧으면 문맥 교환이 잦아져 시스템 성능이 저하되고,
    - 너무 길면 실시간성 요구가 높은 시스템에서 반응 속도가 떨어질 수 있음 
 
<br>

- **블록(Block)**
  - 실행 중인 프로세스가 입출력(I/O) 요청이나 특정 이벤트를 기다려야 할 때, 스스로 CPU를 반납하고 **대기 상태**로 전이
  - 대기 상태에서는 입출력 작업이나 필요한 작업이 완료될 때까지 CPU를 할당받지 않음
  - 주로 I/O 처리나 프로세스 간 통신(IPC) 중에서 발생

<br>

- **Wake-Up**
  -  입출력(I/O) 작업이 완료되면, 대기 상태에 있던 프로세스에게 입출력 종료 사실을 알림
  -  프로세스 상태가 대기 → 준비 상태로 전이되어 CPU 할당 대기 상태가 됨

<br>

- **Swap-In**
  - 프로세스가 디스크 등의 보조 기억장치에서 다시 메인 메모리로 적재될 때 발생

<br>

- **Swap-Out**
  - 메모리 부족 등 이유로 프로세스를 메모리에서 보조 기억장치(디스크)로 내보내는 과정

<br>

### 프로세스 제어 블랙(Process Control Block, PCB)
- 운영체제가 **각 프로세스를 식별하고 관리하기 위한 핵심 자료구조**  
- 프로세스가 생성되면 운영체제는 해당 프로세스에 대한 정보를 담은 고유한 PCB를 생성
- 동작 방식:
  - 프로세스는 CPU를 할당받아 작업을 수행하다가 문맥 전환(Context Switch)이 발생하면, 현재까지의 실행 정보를 PCB에 저장하고 CPU를 반환
  - 이후 다시 CPU를 할당받게 되면 PCB에 저장된 정보를 불러와 중단된 지점부터 다시 실행을 이어감

<br>

**문맥 전환(Context Switch)**
- CPU가 다른 프로세스로 전환되기 위해 현재 프로세스의 상태를 PCB에 저장하고, 새로 실행할 프로세스의 PCV를 로딩하는 과정
- 이 과정은 **시간과 자원이 많이 드는 작업**이므로, 가능한 최소화하는 것이 성능에 중요

<br>
<br>

## 스레드(Thread)
- 프로세스 내에서 **실제로 명령어를 실행하는 단위**
- 하나의 프로세스는 여러 스레드를 가질 수 있으며, 이들은 자원(Code, Data, Heap)을 공유하지만 **Stack은 독립적으로 유지**
- 스레드 간 전환은 프로세스 간 전환보다 훨씬 가볍고 빠름

<br>

### 멀티 스레딩(Multithreading)
- 하나의 프로세스 안에서 여러 스레드가 동시에 작업을 수행하도록 설계하는 기법
- 장점:
  - 자원 공유로 인한 **메모리 효율 증가**
  - 문맥 전환 비용이 낮아져 **성능 향상**
  - I/O 작업 대기 중에도 다른 작업이 가능하여 **응답성 개선**

<br>

### 스택을 스레드마다 독립적으로 할당하는 이유
- 함수 호출 시 사용하는 이자, 리턴 주소, 지역 변수 등이 저장되는 공간이기 때문에 **스레드마다 고유한 실행 흐름**을 유지하려면 **스택은 반드시 독립적이어야 함**
- 여러 스레드가 하나의 스택을 공유할 경우, 함수 호출 정보가 뒤섞여 실행 흐름이 무너짐

> 💡 즉, 하나의 프로세스에 여러 스레드가 있을 경우, **Heap, Code, Data는 공유**하고 **Stack은 독립적**이라는 점이 멀티 스레딩의 핵심 포인트
