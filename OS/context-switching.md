# PCB(Process Control Block), 문맥 교환(Context Switching)

## PCB(Process Control Block)
### 정의
- 운영체제가 **각 프로세스의 상태와 실행 정보를 저장**하기 위해 사용하는 데이터 구조
- **하나의 PCB는 하나의 프로세스 정보만 저장**하며, 이를 통해 프로세스를 관리하고 제어

<br>

### PCB에 저장되는 주요 정보
- 프로세스 상태 (Ready, Running, Waiting 등)
- 프로세스 ID (PID)
- CPU 레지스터 정보 (프로그램 카운터, 스택 포인터 등 현재 실행 중인 위치 정보)
- 메모리 관리 정보 (주소 공간 정보 등)
- 입출력 상태 및 보안/권한 정보   

<br>

> PCB는 CPU가 다른 작업으로 전환될 때, **현재 프로세스의 상태를 저장**해 두는 역할을 합니다. 다시 실행할 때 이 정보를 **복원**하여 작업을 이어갈 수 있도록 합니다.

## 문맥 교환(Context Switching)
### 정의
- CPU가 **현재 실행 중인 프로세스의 상태를 PCB에 저장**하고, 다른 프로세스의 상태 정보를 PCB에서 읽어 **CPU에서 실행 상태로 전환**하는 과정

<br>

> **왜 필요한가?**
>
> CPU는 한 번에 하나의 프로세스만 실행할 수 있기 때문에, 여러 프로세스가 번갈아가며 실행되도록 상태를 저장하고 복원해야 함

<br>

### 문맥 교환이 발생하는 경우
- **인터럽트 발생**
  - 외부 장치 요청, 타이머 등 이벤트 처리 필요 시
    
- **CPU 할당 시간 종료**
  - 운영체제에서 정한 시간 동안 CPU를 쓴 후 양보
    
- **입출력 대기 상태로 전환**
  - 프로세스가 I/O 작업을 기다릴 때
    
- **우선순위가 높은 프로세스가 실행 대기**
  - 선점형 스케줄링 시

<br>

### 문맥 교환 과정
1. 현재 실행 중인 프로세스의 CPU 레지스터, 프로그램 카운터 등 상태를 PCB에 저장
2. 현재 프로세스 상태를 적절히 변경 (예: Running → Ready, Waiting 등)
3. 다음 실행할 프로세스의 PCB에서 이전에 저장된 상태 정보를 읽음
4. CPU 레지스터와 프로그램 카운터 등을 복원하여 해당 프로세스의 실행 재개

<br>

### 문맥 교환의 특징 및 영향
- 장점
  - 여러 프로세를 동시에 실행하는 것처럼 보이게 하여 시스템 자원 효율 극대화
  - 사용자 입장에서 부드러운 멀티태스킹 환경 제공 

- 단점
  - PCB 저장·복원과 CPU 상태 변경에 시간이 소모되어 시스템 오버헤드 발생
  - 문맥 교환이 잦으면 전체 시스템 성능 저하 가능
