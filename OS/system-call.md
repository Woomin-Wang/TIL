## 1. 커널 (Kernel)

### 1.1 커널이란?

![image](https://github.com/user-attachments/assets/35c1d922-c956-494a-85c7-f8af5ed8278c)

**커널은 운영체제의 핵심 부분**이자, 컴퓨터가 켜진 순간부터 꺼질 때까지 메모리에 항상 상주하는 프로그램이다.  

운영체제의 모든 기능이 메모리에 올라와 있을 필요는 없기 때문에, **운영체제 중 가장 필수적이고 빈번하게 사용되는 부분만을 메모리에 올려놓는데, 이 부분이 바로 커널**이다.  

**커널은 응용 프로그램과 하드웨어 사이의 인터페이스 역할**을 하며, **응용 프로그램이 하드웨어 자원을 직접 사용할 수 없도록 하고**, 대신 커널을 통해 안전하고 효율적으로 자원을 사용할 수 있도록 중재한다.

<br>

### 1.2 커널의 주요 역할

커널은 컴퓨터의 핵심 자원들을 관리하고 제어하는 중추적인 역할을 수행한다.

- **프로세스 관리:** CPU를 여러 프로세스에 할당하고, 프로세스의 생성, 종료, 스케줄링 등을 관리

- **메모리 관리:** 물리적인 메모리르 추상적인 공간(페이지, 세그먼트)으로 할당하고, 프로세스들이 서로의 메모리 영역을 침범하지 않도록 보호

- **파일 시스템 관리:** 물리적 저장 장치인 디스크를 추상적인 파일과 디렉토리로 관리하며, 파일의 생성, 삭제, 읽기, 쓰기 등을 처리

- **장치 관리:** 각종 입출력 장치에 대한 접근을 제어하고 관리하며 각 장치에 대한 드라이버를 포함

- **네트워크 관리:** 네트워크 장치를 추상적은 소켓으로 관리하며, 통신을 위한 연결 생성 및 데이터 송수신을 담당

- **인터럽트 처리:** 하드웨어 또는 소프트웨어로부터 발생하는 인터럽트를 처리하여 시스템의 안정성을 유지

<br>

### 1.3 이중 모드: 사용자 모드와 커널 모드

운영체제는 **시스템의 보안과 안정성**을 위해 **CPU를 두 가지 모드로 구분**해서 사용한다.

- **사용자 모드(User Mode)**
  - **일반적인 응용 프로그램이 실행**되는 모드이다.
  - 이 모드에서는 **하드웨어 자원(디스크, I/O 장치 등)에 직접 접근할 수 없다.**
  
**커널 모드(Kernel Mode)**
  - 운영체제, 즉 **커널이 CPU를 사용하는 모드**이다.
  - 이 모드에서는 **모든 하드웨어 자원에 대한 접근 권한이 있으며**, **특권명령을 실행**할 수 있다.
  - 시스템의 중요한 작업은 반드시 커널 모드에서 이루어진다.

<br>

CPU는 **모드 비트**(Mode Bit)라는 플래그를 통해 현재 어떤 모드에서 실행 중인지를 구분한다. (예: `1`이면 사용자 모드, `0`이면 커널 모드)

<br>

> 💡 **특권 명령(privileged instruction)**
>
> 오직, **커널 모드에서만 실행할 수 있는 명령어**를 말한다.  
> 사용자 모드에서는 실행할 수 없으며, 만약 시도하면 예외(인터럽트)가 발생하여 시스템이 이를 막는다.
>
> 예: `I/O 명령`, `인터럽트 조작`, `메모리 관리`, `CPU 제어`, `시스템 종료`

<br>
<br>


## 2. 시스템 콜 (System Call)

### 2.1 시스템 콜이란

시스템 콜은 **응용 프로그램이 커널의 기능을 사용하기 위해 커널에게 서비스를 요청하는 인터페이스**이다.    

**사용자 모드에서 실행되는 응용 프로그램은 하드웨어에 직접 접근할 수 없기 때문에** 파일 입출력, 프로세스 생성, 네트워크 통신 등과 같은 **시스템 자원을 사용하는 작업**은 반드시 **커널에게 요청**해야한다.    

이때 이러한 요청을 **커널에게 전달하는 공식적인 방법이 바로 시스템 콜**이다.

![image](https://github.com/user-attachments/assets/e3c9f8bc-2563-49e8-8d5f-abd2eb6418fb)

시스템 콜은 내부적으로 **소프트웨어 인터럽트가 발생해 CPU는 커널 모드로 전환**되고, 커널이 요청을 직접 처리한 뒤 다시 사용자 모드로 돌아온다.

<br>

> 💡 **소프트웨어 인터럽트(Software Interrupt)란?**
>
> 우선, 인터럽트란 **CPU가 프로그램을 실행하는 도중에 외부 또는 내부에서 발생한 예외적인 상황을 CPU에게 알려주는 신호**이다.
>
> 그중 소프트웨어 인터럽트는 프로그램 내부에서 명령어(`trap`, `syscall` 등)를 통해 **의도적으로 발생시키는 인터럽트로, 보통 시스템 콜 실행 시에 사용**된다.

<br>
<br>

## 2.2 시스템 콜의 처리 과정

### **일반적인 연산 (사용자 모드)**

**1. 응용 프로그램 실행**
- 응용 프로그램이 메모리 상의 코드를 실행하며, 이때 CPU는 **사용자 모드 상태로 동작**한다.

**2. 명령어 직접 전달**
- 응용 프로그램의 명령어들은 **커널의 중재 없이 곧바로 CPU에게 전달된다.** 

**3. CPU 실행**
- CPU는 전달받은 명령어를 사용자 모드 그대로 실행한다.
- 이 과정에서 프로그램에 할당된 메모리 영역 내에서만 작업이 이루어지며, **디스크나 네트워크 같은 외부 하드웨어에는 접근하지 않는다.**

**4. 작업 완료**
- CPU는 계산 결과를 프로그램의 메모리에 저장하고 다음 명령어를 실행한다.

> ✅ 일반적인 명령은 CPU가 사용자 모드에서 응용 프로그램으로부터 **직접 지시를 받아 처리하며, 이 과정에서 커널은 개입하지 않는다.**

<br>
<br>


### **하드웨어 자원 이용 (시스템 콜을 통한 커널 모드)**

**1. 시스템 콜 호출**
- 응용 프로그램이 하드웨어 자원을 사용하기 위해 `open()`, `write()` 같은 **시스템 콜 관련 함수를 호출**한다.

**2. `trap` 명령어 실행**
- 시스템 콜 함수 내부에는 **소프트웨어 인터럽트인 `trap` 명령어가 포함**되어있다.
- CPU는 이를 감지하면 커널 모드로 전환할 준비를 한다.

**3. CPU의 즉각적인 모드 전환 및 문맥 저장**
- CPU는 `trap` 명령어를 감지하는 즉시, 커널의 개입이 필요한 상황이라고 인지한다.
- CPU는 사용자 모드에서 **커널 모드로 즉시 전환**하며, 이때부터 특권 명령을 실행할 권한을 갖는다.
- 동시에, **현재 실행 중이던 응용 프로그램의 상태(문맥)를 커널 스택에 저장**한다.

**4. 제어권 커널에게 전달**
- CPU는 모드 전환과 문맥 저장을 완료한 후, 미리 정해진 **커널의 시스템 콜 처리 루틴으로 제어권을 넘긴다.**

**5. 커널의 지시 및 CPU 실행**
- 이제 커널이 지시자가 되며, 어떤 시스템 콜 요청이 들어왔는지 확인한다.
- 커널은 커널 모드의 상태 CPU에게 하드웨어 자원을 제어하기 위한 특권 명령들을 순차적을 실행하라고 지시한다.
- CPU는 커널의 지시를 받아 하드웨어와 직접 소통하며 요청된 작업을 수행한다.

**6. 사용자 모드 복귀**
- 작업이 완료되면, 커널은 `return from trap` 명령어를 실행하여 CPU에게 사용자 모드로 복귀할 것을 명령한다.
- CPU는 다시 사용자 모드로 전환하고, 저장해 두었던 응용 프로그램의 상태(문맥)을 복원하여 원래 하던 작업을 이어간다.

<br>
<br>

### 2.3 시스템 콜의 필요성 및 장점

- **보안 및 안정성 강화**
  - 사용자 프로그램이 하드웨어에 직접 접근하지 못하게 막고, 커널이 대신 자원 접근을 통제함으로써 시스텀 전체를 보호한다.

- **추상화된 인터페이스 제공**
  - 시스템 콜은 복잡한 하드웨어 동작을 감추고, 간단한 함수 형태로 제공된다.
  - `read()`, `write()`는 실제로는 복잡한 디바이스 제어와 메모리 관리를 포함하고 있다.

- **이식성 향상**
  - 응용 프로그램은 시스템 콜만 사용하면 되므로, 운영체제가 달라서 같은 API가 구현되어 있다면 재사용성이 높다.
